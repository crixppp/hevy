# Metric contract · v1 (written before analytics)

All views share this contract. Source = Hevy, stable workout UUID and exercise template ID; exercise appearances and sets use source indices. Raw records remain intact. Analytics version changes invalidate saved forecasts.

- Calendar dates and Monday–Sunday weeks use Australia/Melbourne, including DST. Range bounds are inclusive local dates. Session elapsed minutes = (end − start)/60,000; invalid/negative intervals are missing.
- Working sets: normal, failure, dropset. Warmups are counted separately. Unknown types are excluded and flagged. Dropsets are individual recorded sets; not equivalent stimulus to straight sets.
- Null ≠ zero. Negative/invalid weight, reps, duration, distance or RPE outside 0–10 are flagged and excluded from the affected metric, never rewritten. No imputation. RPE is subjective; coverage denominator is eligible working sets.
- Volume load = Σ recorded external kg × recorded reps when both are valid. Zero external load contributes zero. No automatic doubling for dumbbells/unilateral reps, no bodyweight additions. Unknown conventions are labelled unresolved. Assisted/bodyweight profiles do not contribute to external-load/e1RM comparisons. Volume is not mechanical work and totals across equipment are descriptive only.
- Estimated 1RM = Epley: kg × (1 + reps/30), for external-load, reviewed equipment profiles and 1–10 reps. One rep returns recorded kg. Positive load required. No RPE adjustment. Session value = max eligible set. Not a physiological measurement; especially limited on machines.
- Exercise series never join different stable IDs. Equipment profiles have effective start/end dates, load increments and convention descriptions. Profile changes split series. Optional alias mappings are descriptive only; do not silently pool performance. Movement/muscle mappings are user inputs; only direct set counts, no implicit indirect fractions.
- Sessions, days, durations, sets and exposure are facts/calculations. Bests refer only to imported history. No workout recorded ≠ no activity. Frequency = sessions / inclusive days × 7; incomplete periods clearly labelled. Percent change with a zero denominator is unavailable.
- Blocks: compare inclusive dates, sessions/week, sets/week, actual observation counts and overlapping exercises within the same reviewed profile; no programme ranking. Context is not evidence of causation.
- Goals: exact exercise/profile and metric; rep target uses best external load at exactly the specified reps, optional RPE ceiling requires recorded RPE. Weekly goals only assess complete weeks. Distance/duration goals use valid recorded quantities. Achievement needs source evidence, not a forecast.
- Forecast v1: comparable session e1RM, reviewed equipment, at least 8 observations across 42 days; last 120 days only. Last 3 observations are chronological holdouts. Theil–Sen median pair slope on prior observations; compare holdout MAE against last-value baseline. Fit all available observations only after evaluation; use trend only if it beats baseline, otherwise explicitly use no-change baseline. Forecast horizon 7–42 days. Variation envelope = ±2 × holdout MAE, heuristic, not a confidence interval. No promised goal date or causal frequency effects. Flat/negative trends remain flat/negative. Round display to equipment increment; preserve numeric forecast in snapshots.
- Snapshots store cutoff, source fingerprint, model/version, profile, goal, target date, eligibility and assumptions. Target = first eligible recorded observation on/after target date within 14 days. No retargeting. If pre-cutoff source fingerprint changes, mark revised/unscorable; if target observation changes, rescore against current source and label revision. Errors = observed − predicted (negative means overprediction); insufficient completed snapshots ≠ calibrated reliability.

Views offer traceable source rows and text alternatives to charts. Dates, coverage and sample sizes accompany interpretation. Derived data stays in application memory; no personal response cache or analytics tracking.
